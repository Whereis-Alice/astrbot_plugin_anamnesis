# 3.5.0：档案、时间查询与管理工作流

本版参考 Memorix 1.4.0 的事实账本、人工画像覆盖、操作恢复、事件证据和版本化索引待办，在 Anamnesis 的现有存储、身份、会话、人格和生命周期边界内实现。

建议更新到 **3.5.11**：包含先前全部修复，并补充关闭原子记忆时的完整摘要回退及待写事实保留、会话迁移前的派生证据与恢复日志核验，以及旧归档恢复取消时的字段完整补偿。以下功能与默认值继续适用。

## 用户档案

档案默认仍关闭。启用后，自动提取仍只接受本人明确自述，检查置信度与原话引文，不推断性格或把他人的转述写成本人事实。

- 初次有效自述可成为当前资料；同属性的新说法默认进入待审核区。
- WebUI 人工修改有独立优先级，自动提取不会覆盖人工值。关闭人工覆盖开关也不会解除已有保护。
- 每项资料可以有多份原话证据，并显示旧值、当前权限来源、待审核变化和来源会话。
- 删除或归档一份自动证据后，检查其他来源；最后一份有效证据失效才暂停自动资料注入。人工确认是独立来源。
- 接受、拒绝、解除保护和编辑检查当前版本，旧页面不能覆盖后来修改。
- 管理员可以给明确账号设置显示别名；别名不改变账号身份，也不合并重名用户。

目录合并展示同一个用户，事实仍按配置的 session/user 范围作用。默认按会话隔离；普通记忆继续执行人格过滤。`/new` 不清空长期数据。

相关设置：`user_profile.manual_override_enabled`、`review_changes`、`history_max_versions`、`evidence_max_sources`。历史记录不会因迁移自动变成人工确认资料。

## 时间与图召回

`recall_engine.temporal_retrieval_enabled` 默认开启。自动召回与回忆工具支持“昨天、上周、某日至某日”等时间表达，纯时间问题直接读取时间范围内的候选，混合问题融合时间和语义结果。

时间使用 `[start,end)`，优先插件明确时区，再使用 AstrBot 会话配置中的时区。事件时间与创建时间在查询解释中区分；范围、候选数量和总检索超时都有预算。当前作用域、人格、归档状态及事实期限在分配名额前后校验。

`graph_memory.graph_evidence_enabled` 默认关闭。开启后，图关系得到原文支持才取得相应图分数与多路命中奖励，分路得分包含支持率、覆盖率和门控结果。这些分数用于排序，不代表事实真伪概率。

## 管理工作台

新增页面统一管理恢复、纠正、导入、评测、事件及索引同步。页面随插件构建分发，管理员通过 AstrBot 原生页面鉴权访问。

### 删除与恢复

“移入恢复中心”保存操作编号和来源快照，通过已有归档流程退出检索。可以整次恢复，也可显式永久销毁。恢复核验操作归属、正文、来源、作用域及后续变更；有冲突的记录保留现状并报告。

原有永久删除仍然是永久删除。LLM 遗忘工具可选择 `agent_tools.forget_mode=recoverable`，加入同一恢复中心；该工具仍默认关闭，保留原有额度、冷却与会话/人格检查。

### 纠正计划

填写一个确切记忆 ID 与自然语言说明，生成修改前后预览；也可直接填写新正文，跳过模型。点击确认后，服务端签发绑定管理员的一次性短期凭据，执行前再次检查原文版本。

`agent_tools.enable_correction_plan_tool` 默认关闭。启用后，管理员在当前聊天和人格内可以让 LLM 提出计划；工具不能确认或执行。执行后的记忆可以回滚，回滚拒绝覆盖后来变化，原事实寿命不会重新开始。

### 导入任务

支持粘贴、多个文件及浏览器选择的文件夹，格式为 TXT/Markdown/JSON/CSV。文本资料按段落或标题有界分块，必须指定作用域；原生 JSON/CSV 保留其明确作用域与生命周期。

任务和分块状态持久保存，完成的块不会在重试时再次写入。任务串行执行，取消在已提交分块后停止；重启后的在途任务标为中断，由管理员明确重试。源文件名称保留为出处，不读取服务器任意路径。

### 固定查询评测

提供独立的查询与期望记忆 ID，可包含应为空的查询。报告正确的 Hit@K、Precision@K、Recall@K、MRR、空结果准确率、错误和时延，以及查询集和配置指纹。评测不强化访问次数，也不自动应用配置。

创建任务时固定参考时间、会话时区和配置指纹，重试使用同一参考；配置已经改变时应新建评测。查询示例：`[{"query":"昨天聊过什么","expected_ids":[123],"mode":"auto"},{"query":"不存在的资料","expected_ids":[]}]`。召回调试页也支持模式、起止时间与人格；管理员留空人格表示查看全部人格。

同一查询集可在调整配置前后分别运行，以报告比较；本版不声称某个默认算法已经在你的数据上更准确。

## 可关闭的事件层

`episodic_memory.enabled` 默认关闭。启用后，管理员选择同作用域、人格和来源会话的记忆，按需生成事件标题、经过与成员证据；也可关闭本次模型生成，保存证据摘录。

不新增独立事件向量库。召回通过词法和命中文档投影到事件，仍在原整体检索超时内，注入有独立字符预算。证据归档、删除、过期或修改后，旧摘要停止展示和注入；管理页可从当前有效证据重新生成。重建检查事件版本。

点击事件的“重新生成”会先打开来源核对窗口，显示原记忆 ID、记忆范围、人格和来源会话。来源被纠正、删除或过期时，请在“记忆管理”中找到当前有效的记忆 ID，再替换或移除失效的 ID；插件不会自动猜测替换关系。可以选择模型总结或证据摘录，取消不会提交任务，生成失败时保留原事件；事件已经更新时，需要刷新后重新核对。

## 索引一致性与预算

文档变化与版本化索引待办由同一 SQLite 事务提交；旧任务完成不能清除新的版本。管理工作台可以提交有预算的同步任务，读取当前主数据，不复活已过期原子。原有写操作修复、补偿和影子重建继续保留。

`memory_administration` 包含各功能开关、保留期、记录数、快照与输入容量、分块和 Provider 超时预算。保留中的恢复数据不会因达到容量上限被自动丢弃，需要管理员显式处理。

| 配置项 | 默认 | 用途 |
| --- | --- | --- |
| `user_profile.manual_override_enabled` / `review_changes` | `true` / `true` | 人工保护与新自动值审核 |
| `user_profile.history_max_versions` / `evidence_max_sources` | `20` / `20` | 每项历史与证据容量 |
| `recall_engine.temporal_candidate_limit` | `500` | 时间查询候选预算 |
| `recall_engine.temporal_max_range_days` | `3660` | 最长查询范围 |
| `recall_engine.temporal_timezone` | 空 | 跟随 AstrBot 时区，可填写 IANA 时区 |
| `graph_memory.graph_evidence_min_support` | `0.5` | 可选图证据门控支持阈值 |
| `memory_administration.retention_days` / `max_records` | `30` / `500` | 计划恢复期限与记录数量 |
| `memory_administration.max_storage_mib` / `max_snapshot_kib` | `128` / `1024` | 管理数据总量与单条来源快照预算 |
| `memory_administration.max_job_mib` / `max_import_chunks` | `5` / `1000` | 任务输入与导入分块容量 |

纠正与回滚在删除旧副本前保存准备日志；中断后核验已有副本，可继续回滚。后续人工变更造成冲突时保留现状。卸载会等待任务准备、当前写入及状态持久化收尾。
