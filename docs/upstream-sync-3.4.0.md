# 3.4.0：上游适配与档案重做

本次继续参考 LivingMemory **2.7.1**（提交 `b8aaaec2c1232ec2c86fce22cec066a0069018e0`），在 Anamnesis 3.3.0 上适配剩余能力。工具名、用户身份、会话和人格边界沿用本插件规则。

## 用户档案

打开「插件 → Anamnesis → Pages → dashboard → 用户档案」。先从用户目录找人，再阅读完整资料。支持姓名、账号、最近已知群名和来源会话筛选；同一身份的事实按类别阅读，各聊天来源分段。每条事实可以查看全文、编辑、删除或跳转到来源记忆，窄窗口和键盘操作均可用。

目录聚合不改变数据库作用域。编辑、删除仍使用准确的 `profile_scope` 和 key；`user_profile.scope_mode` 默认 `session`，档案注入仍按会话隔离。昵称别名影响目录身份，旧数据根据完整来源会话后缀安全回填。新提取事实使用易读标题，旧事实有标题后备。

从 3.4.2 起，目录的最近群名独立于事实出处保存，聊天来源分段使用每条事实的原始来源会话；缺少账号的事件不建立档案。来源已失效的条目不会占用有效档案的注入名额。

## 检索与生命周期

向量检索在作用域过滤后不足 Top-K 时逐步扩窗，默认最多检查 8192 个候选。同轮文档路与图路复用 Embedding 和已检查 ID，包括缺失或被过滤的 ID。只提供旧 `retrieve` 接口的宿主保留扩窗兼容，其内部 Embedding 无法跨轮次复用。

`recall_engine.fusion_mode` 默认 `rrf`，保持原排序；可选 `score` 使用归一化相关度、BM25 权重和两路共识奖励。score 默认候选倍数 3、BM25 权重 0.5、共识奖励 0.25。

原子 FTS 启动时按 ID、内容与状态对账，补漏并清理失效行。原子关键词候选接入主召回；过期事实从正文、人格摘要、规范摘要和事实字段一起去掉。缓存重新验证文档存在性、状态和原子期限。

图读取复用只读连接。访问统计在短时间内合并事务，保留每轮真实次数，卸载时刷新队列；独立 SQLite 连接和有界锁重试保留。向量删除失败或接口缺失持久标记重建。FAISS 导入和整索引读取移出事件循环；请求期用就绪快照判断是否启用记忆。

## 总结与保守合并

用户消息优先使用平台时间，支持毫秒时间戳。`reflection_engine.split_by_day=true`，按 AstrBot 时区分日；`idle_gap_minutes=180`，0 关闭空闲分段。同轮问答不拆开，已封口的短窗口可先总结，新窗口继续积累。

WebChat 有 checkpoint 时，编辑或重新生成对齐历史尾部，撤销的消息及相关总结失效；头部缺失按上下文压缩保留。总结执行前后及保存后验证修订号，并补偿失效任务的记忆和档案。没有可靠 checkpoint 的平台保持保守行为。

`reflection_engine.dedup_enabled` 默认关闭。启用后只合并同作用域、人格、源聊天与身份，事实完全一致且文本足够接近的总结；默认文本阈值 0.97。否定、数值和新事实变化会另存。合并保留原 ID 和摘要，追加来源窗口及保留原文，不用相似向量替换新事实。

从 3.4.1 起，可回退的总结还要求来源消息窗口相同；不同轮次另存，撤回新消息不会连带删除旧消息支持的记忆。带消息 ID 的总结使用相同的有效 ID 集合判断，旧版仅有修订号的总结要求来源窗口完全一致。

## 分步回忆与遗忘工具

启用 `agent_tools.agentic_recall_enabled` 后，`anamnesis_recall_memory` 增加 `speaker`、`start_time`、`end_time`、`exclude_ids`、`cursor`，另注册 `anamnesis_read_memory_evidence` 读取保留原文。人物按准确账号或名称匹配；时间依次使用事件时间、来源消息时间范围、记忆创建时间，并注明依据。时间参数接受 Unix 秒或 ISO-8601，无时区的值按 UTC 解释。

候选池默认 100 条，筛选和游标基于有界候选，不承诺遍历全库。检索与证据读取共用每轮 5 次调用、20 秒累计执行时间和 16000 字符输出预算。原文读取额外核实来源会话，避免全局或旧版不筛选召回扩大原文访问范围。历史原文可能包含已被纠正的发言，返回有效事实及生命周期信息供判断。

`anamnesis_forget_memory` 保留明确 ID、原因及归属核验。`agent_tools.forget_mode` 默认 `delete`，永久删除；`archive` 可恢复归档。归档暂停相关档案注入并保存原子原始期限；恢复不重置 TTL，不覆盖之后由其他来源写入的档案纠正。工具支持 `action=restore`；默认每轮最多 3 次操作，同作用域冷却 2 秒（0 关闭），记录有界审计日志。

## 显式作用域迁移

从 3.4.2 起，运行时自动迁移只接受 `source_session_id` 或 `source_window.session_id` 明确且一致地指向目标完整会话的旧记录。仅有数字 ID、缺失或冲突来源的记录保留原状，日志提示管理员使用以下命令预览。迁移期间会创建数据库备份并同步原子与图数据；图谱正在重建或选中文档仍在写入时，需要等待完成后重新预览和重试。

管理员命令：

```text
/anam migrate-scope <源作用域> <目标作用域>
/anam migrate-scope <源作用域> <目标作用域> backup <预览指纹>
/anam migrate-scope <源作用域> <目标作用域> apply <预览指纹>
```

默认只预览。限制人格时，在参数末尾附上人格 ID（预览需显式填 `preview` 和占位指纹 `-`）。执行前核实指纹并创建 SQLite 备份；数据变化时必须重新预览。迁移同步文档、原子、图条目和图向量元数据，保留源会话与人格，不改变个人档案作用域或共享配置。常规失败回滚并提供备份；WAL 多文件不能保证整机掉电时跨文件原子恢复，备份保留在插件数据目录的 `scope-backups`。

## 设置与构建

dashboard 新增独立设置页，按配置 schema 展示分类、搜索、折叠和常用项。保存先校验再持久化，需要重载插件后统一生效；AstrBot 原配置页仍可使用。

记忆与图谱可相互跳转，详情展示来源、记录原因和各路分数。系统与提示词页的失败提示持续可见并可重试。图标使用本地 Lucide 子集，源码保留；`npm run dashboard:build` 生成提交资源，`npm run dashboard:check` 检查是否同步。
